# teeup-fetch

Teeup の、楽天GORAからプランを取り込む部分です。

置き場所を分けているのは GitHub Actions の分数のためです。private
リポジトリの Actions には月ごとの上限がありますが、public には
ありません。この取り込みは1日17時間動くので、本体（private）から
切り出しています。

接続先とAPIキーはリポジトリシークレットに入れてあり、
ここには入っていません。

## 何をしているか

全国1,907コースについて、61日先までのプランを毎日取りに行きます。
楽天は1秒1件までしか受けないので、それを守って順に引きます。

日付は近いほど密に見ます。近い日ほど値段が動き、実際に予約される
のも近い日だからです。

    14日先まで   毎日
    15〜30日先   3日おき
    31〜61日先   7日おき

1コースあたり23日ぶん。全国で1日42,259回になります。1つの仕事は
6時間で切れるので、コースを4つの組に分けて1日4回に散らしています。

| 組 | 時刻(JST) | 範囲 | コース | 見込み |
|---|---|---|---|---|
| 0 | 02:00 | 関東6県 | 526 | 298分 |
| 1 | 08:00 | 東日本 | 464 | 263分 |
| 2 | 14:00 | 中部・近畿 | 424 | 240分 |
| 3 | 20:00 | 西日本 | 493 | 279分 |

間隔は6時間ずつにそろえてある。枠は各330分。

県のまとまりより1回あたりの量をそろえるほうを優先しているので、
兵庫は西日本、岡山・鳥取・島根は中部・近畿に入れてある。

どのコースがどの組かは、その場で決めずデータベースに持たせて
あります（`course.fetch_group`）。途中で時間切れになっても、
次の日の同じ回が同じ並びの続きから拾えるようにするためです。

## オープンコンペ（compe.mjs）

日ごとの取り込みは61日のうち23日しか見ません。31〜61日先は7日おきに
しか当たらないので、単一日程のオープンコンペは当たらなかった日の
開催がまるごと落ちます。実際 11/8 の関東だけで154件ありましたが、
その日は見ていませんでした。

楽天のプラン検索は `planOpenCompe=1` でコンペだけに絞れ、`areaCode` で
地域ごとにまとめて引けます。コース単位ではなく「日×地方」で引けば
61日ぶん全部拾えます。18:10 JST に約100分かけて回します。

全国を1度に引くと件数が488で頭打ちになるので、8地方に分けています。

## 手で回す

Actions の画面から「プランを取り込む」→ Run workflow で、
組と分数を指定して回せます。

## 必要なシークレット

    DATABASE_URL
    RAKUTEN_APP_ID
    RAKUTEN_ACCESS_KEY
    RAKUTEN_AFFILIATE_ID
